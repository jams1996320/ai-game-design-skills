# 视频 → 透明 PNG 序列（测试版）

## 合同与边界

使用者已保证主体颜色与背景不同，不重复要求确认。背景预期为稳定纯色；颜色未知时先检测。继承上游动画 ID、帧率、循环和命名要求，缺省保留尺寸和源视频名义帧率。可变帧率源会转成固定帧率，须告知用户。不要自动裁掉动作停顿、逐帧紧裁、补帧或改变角色位置。

在本地执行，不上传素材。第一版只有 FFmpeg、Python/OpenCV/NumPy/Pillow；没有 SAM、云服务或生成式修图。Codex 分析问题并调用脚本，不宣称聊天模型直接输出精确像素遮罩。用户要求另接服务时再单独处理。

## 1. 自动准备环境

主要部署目标为 Windows x64（员工电脑），推荐 Python 3.12；macOS/Linux 是辅助开发/测试路径。Windows ARM64/32 位不在当前自动安装支持范围。员工只负责提供文件和审核，不要求员工理解或运行命令。

先读 [环境与执行参考](references/usage.md)。检查受管运行环境是否可用；缺失时由 Codex 执行安装脚本，不能只把命令交给不熟悉终端的用户。

- Windows：运行 `scripts/setup-windows.ps1`，检测 Python，缺失时通过 winget 用户范围安装，再建立独立 venv。
- macOS/Linux：用可用 Python 3.9–3.12 执行 `scripts/setup.py`。没有 Python 时按系统提供的包管理方式处理，不假定系统带 Python。
- 依赖通过 PyPI 的固定版本 wheel 安装；imageio-ffmpeg 包提供 FFmpeg，优先复用 PATH 中已有 FFmpeg。不需要 ffprobe，视频帧率由 OpenCV 读取。
- 使用安装脚本返回的 Python 完整路径，不修改全局 PATH、永久执行策略或管理员配置。系统授权/组织限制无法绕过时说明具体阻碍。
- Windows 安装脚本尚未在真实 Windows 验证，不能声称全平台测试通过。依赖不支持当前架构时停止并报告，不静默改成源码编译。

## 2. 本地批量抠像

运行 `process.py process --video <MP4> --out <全新任务目录>`，可按交接添加 `--prefix`、`--fps`。路径使用参数数组或正确引号。输出不能覆盖已有目录。

脚本解码保留无损原始 PNG，最多采样 9 个时间点边缘估计底色，以同一颜色批量执行 FFmpeg colorkey。检测不确定时会停止：查看 source 中的代表帧，确认稳定底色后显式传 `--color '#RRGGBB'`，用新目录重跑。不要无限放宽参数去强行通过。

查看首尾、动作极值和快动作处的对照结果。初始 similarity=.12、blend=.08 只是试用起点；必要时试 1–2 组参数，累计最多 3 次自动尝试后交给用户审核。保留半透明抗锯齿；不要求所有 Alpha 只能是 0/255。

## 3. 人工审核是明确节点

打开任务目录的 `review.html`：源帧与结果并排，切换黑/白/灰/棋盘底，暂停、逐帧、标记问题。可直接在 Codex 说“35-42 衣服缺失，78 紫边”，也可下载 review.json 后提供。

向用户交付预览和 frames.zip，并明确“待人工审核”。等待审核反馈再修复，不能把自动文件检查写成人工已通过。浏览器播放只是检查辅助，大图可能无法实时解码；用暂停/逐帧检查细节。

## 4. Codex 修复被标记帧

读取原始帧、当前透明帧、相邻帧和 job.json。按原因选择：

- 残底/边缘过硬：`repair --frames ... --similarity ... --blend ...` 重抠。
- 半透明边缘残色：试 `--decontaminate`，利用已知底色作边缘混色反解；Alpha 不准确时可能失真，必须比较前后。
- 主体局部被误删：从原始像素恢复。Codex 可根据实际图像用本地脚本制作同尺寸灰度遮罩，再用 `--restore-mask`；白=恢复为不透明，黑=保留当前结果，灰=最低 Alpha。只用于明确应不透明的主体内部，不可把真实半透明毛发直接涂白。
- 遮罩不应跨运动帧盲目复用。主体移动时为各帧准备相应遮罩，逐次生成修订版本，或只重抠整个问题片段。
- 原片缺肢、变脸、出画：报告源素材问题，不伪装成抠图修复。超过 3 次尝试仍不合格时给出未解决帧号与重新生成建议。

`repair` 必须输出新目录，保存旧版和原始帧；未选择帧保持原文件。把修订预览交回用户复核，并检查相邻帧是否跳变。禁止未经请求使用 image generation 逐张重绘角色。

## 5. 交付

- `frames/`：只放 RGBA PNG（8 bit/通道，共 32 bit/像素），四位连续编号，从 0001 开始，上限 9999。
- `frames.zip`：只包含 frames/ 序列。
- `source/`：未抠底原始帧；`job.json`：帧率、尺寸、参数、修订历史、检查警告；`review.html`：对照审核。
- 文件检查验证编号、尺寸和 RGBA，并提示全透明/不透明帧及前景面积突变；这些是启发式警告，不证明视觉质量。
- 用户明确接受后才能报告人工审核通过；保留审核意见。向工程交付时附帧率和循环要求，PNG 本身不携带动画时序。
